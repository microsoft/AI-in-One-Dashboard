Activity

Usage

Recorded activity within the selected dates, people and experiences. Read the specific metric: prompts, sessions and active users count different things. Usage is not a measure of time saved, answer quality or employee performance.

Calculation or rule
Not a calculated metric. An umbrella label: prompts count request identifiers; sessions count person/thread keys; active users count people. There is no single interchangeable usage unit.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Totals are recalculated in their own filter context, not summed from visible rows. Audit activity is not a measure of output quality, time saved, ROI or employee productivity.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: one person sends five distinct requests in two threads: 5 prompts, 2 sessions and 1 active user.

Model references: PromptsSubmitted, User Sessions, Active Users in Scope

Actions

Recorded action or operation evidence can help describe an inferred usage pattern. It does not by itself prove a task was completed or a business outcome was achieved.

Calculation or rule
Not a calculated metric. Action/operation evidence helps prepare behavior labels; it is not a count of completed tasks. The legacy Actions Per User measure divides recorded licensed non-agent Message_Id values by the matching active people.
Dates, filters and population
Read the displayed label: current Prompts per user labels describe requests, not successful actions.
Assumptions and limitations
Recorded resource operations can repeat for one prompt. Neither a resource row nor an inferred action establishes task completion.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. AccessedResource_Action and other preparation signals inform Behavior_Enriched; the legacy DAX name remains AverageActionsPerUser (Licensed Copilot Only).
Worked example
Synthetic: one request accesses three resources. It is not three completed business actions; with one Message_Id it contributes one prompt.

Model references: AverageActionsPerUser (Licensed Copilot Only)

Prompts

Distinct recorded user request messages, not agent responses. Repeated copies of the same request do not add another prompt; identifier quality affects counts.

Calculation or rule
Count distinct nonblank Message_Id values in the applicable prompt-only activity rows.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Repeated resource/context rows with the same identifier count once. Missing identifiers do not count in PromptsSubmitted. These are recorded user requests, not response messages; identifier and audit coverage quality matter.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. The base formula is DISTINCTCOUNTNOBLANK(Message_Id).
Worked example
Synthetic: IDs A, A, B and blank produce 2 prompts, not 4.

Model references: PromptsSubmitted, PromptsSubmitted - Chat, PromptsSubmitted - Licensed, Agent Prompts

Microsoft Learn: Copilot audit records (opens a new tab)Source context. AIO applies its own prompt selection and counting rules.

Sessions

Distinct person-and-thread conversations in the current selection. The same person returning to the same thread on several days can count once for the whole period.

Calculation or rule
Count distinct User Session Key values. Power Query constructs the key as PersonKey + "|" + ThreadId.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
A session is a person/thread conversation, not an inactivity timeout or duration. Revisits can count on each date but once for the period; different people remain separate. Base DISTINCTCOUNT does not explicitly exclude blank session keys, so incomplete identifiers can distort counts.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. PersonKey resolves license-state UserKey rows to a stable person before the session key is constructed.
Worked example
Synthetic: person A uses thread X on Monday and Tuesday; person B uses X on Tuesday. Daily counts are 1 and 2, but the two-day total is 2.

Model references: User Sessions, Total Sessions (All), Total Agent Sessions, Sessions (Licensed Users Only), Sessions (Unlicensed Users Only)

Prompts per session

Recorded prompts divided by distinct sessions in the same scope. Conversation depth is not duration or business value.

Calculation or rule
Distinct recorded prompts / distinct sessions, evaluated in the same scope.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
This is a ratio of totals, not the unweighted average of people or agent-row ratios. A missing or zero denominator normally gives blank. A deeper conversation may include retries or difficulty.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: 18 prompts across 6 sessions = 3 prompts per session. A second group with 2 prompts/2 sessions gives a combined 20/8 = 2.5, not (3 + 1)/2.

Model references: Average Prompts per Session, Prompts per Session - Chat, Prompts per Session - Licensed, Agent Prompts per Session

Active days per user

Average distinct dates with recorded activity among active users in scope. It is not hours worked or time spent.

Calculation or rule
For each active person count distinct recorded activity dates, then take the mean across active people. Applicable page measures use ActivityDate or the prepared InteractionDate.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Several prompts on one date count as one active day. People without matching activity are not zero-padded into this active-user mean. It is neither hours nor elapsed calendar days.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: active A uses 2 dates and active B uses 4 dates: (2 + 4)/2 = 3 active days per user. Ten inactive directory people do not change that mean.

Model references: Active Days per User, Average Agent Active Days Per User, Average Chat Active Days Per User, Average Chat Active Days Per User (Licensed)

Repeat users and return rate

The share of active users with at least two sessions in the selected period. For agents, 0% means active users but no repeats; blank can mean no activity or protected scope.

Calculation or rule
Repeat users = active people with at least 2 distinct sessions; return rate = repeat people / active people. Agent return uses at least 2 distinct ThreadId values per person.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Within-period repeat use, not previous-month retention. The agent formula coalesces a missing repeat numerator to 0: active people with no repeats give 0%; no eligible denominator normally gives blank.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: of 5 agent users, 2 use at least two threads. Return rate = 2/5 = 40%. Five users each using one thread gives 0%, not missing telemetry.

Model references: Repeat Users, Repeat Usage Rate, Agent Return Rate (Table), Agent Return Rate (KPI)

Daily repeat-session share

The share of active unlicensed Chat users with more than one Chat session that day. This daily measure differs from repeat users across the full period.

Calculation or rule
For each displayed day, count qualifying unlicensed Chat users with more than one session that day and divide by that day's active Chat users.
Dates, filters and population
The daily Chat repeat-rate context, not the whole selected period.
Assumptions and limitations
Using the same thread twice on one day is still one session. A user with one different thread on each of two days can repeat for the whole period while never repeating within a day.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. The Chat repeat measure is evaluated in each Calendar day context.
Worked example
Synthetic: Monday has 4 active Chat users; 1 has two distinct threads. Monday share = 1/4 = 25%. A second thread first used Tuesday does not increase Monday's numerator.

Model references: Repeat Usage Rate

Other AI and Unclassified activity

Other AI can include non-agent autonomous or logic app hosts. Unclassified preserves activity that cannot be confidently assigned; neither category is automatically unlicensed Chat.

Calculation or rule
Classify agents first, then Cowork, then other-product/non-agent autonomous, logic app and Copilot Studio hosts. Remaining licensed rows become M365 Copilot; recognized unlicensed Chat hosts become Copilot Chat; remaining rows stay Unclassified.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Other AI and Unclassified are not automatically unlicensed Chat. Classification is a preparation/model rule, not evidence that every product is fully tracked.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. Power Query Experience and Is Chat Activity transformations use license, AgentId, AppHost, Environment and AppIdentity_DisplayName.
Worked example
Synthetic: an unlicensed non-agent logic app row is Other AI activity. An unrecognized unlicensed non-agent host is Unclassified, not a Chat user.
Audit coverage

Purview audit data supports security and compliance. Coverage, timing and calculations can differ from Viva Insights and the Microsoft 365 admin center; prompts do not measure responses, duration, time saved or performance.

Calculation or rule
Not a calculated metric. Measures summarize the collected audit evidence, not all possible Copilot activity or official cross-product adoption totals.
Dates, filters and population
Purview audit retention, collection dates, product support, preparation and imported report scope.
Assumptions and limitations
Viva Insights and Microsoft 365 admin center can use different coverage, timing and definitions. Prompt-only day-grain data cannot establish response counts, measured duration, hourly/voice usage, savings, revenue or performance.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: the prepared audit file contains 80 distinct prompt IDs and another service reports 100 interactions. The dashboard reports its 80 prompts; it must not invent 20 missing responses.

Prompts per active user

Recorded prompts divided by matching distinct active people in the selected period, not by eligible directory headcount or weeks. The former Actions Per User label refers to licensed non-agent requests.

Calculation or rule
Divide the relevant recorded prompt count by matching distinct active people in the same period/cohort. The licensed usage trend uses nonblank licensed Chat prompts / licensed Chat users; the former Actions Per User field uses licensed non-agent activity.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Not divided by weeks or directory headcount. Display Average Prompts Per Active User (Licensed) uses PromptsSubmitted - Licensed. The separate legacy Actions measure uses DISTINCTCOUNT(Message_Id), which can count a blank once, and excludes agents without the stricter Is Chat Activity test.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. The modern trend and legacy table measures share request units, but have distinct filters and blank-ID handling.
Worked example
Synthetic: 40 distinct nonblank prompts from 5 active licensed non-agent users = 8/user. Twenty inactive licensed people do not change the denominator.

Model references: Display Average Prompts Per Active User (Licensed) - Licensed, AverageActionsPerUser (Licensed Copilot Only)

Sessions per active user

Relevant distinct person/thread sessions divided by matching active people in the same period and cohort. This is not a weekly-normalized rate.

Calculation or rule
Relevant distinct person/thread sessions / matching distinct active people.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
A period total ratio, not a per-week rate. The licensed/unlicensed Chat denominators require qualifying Chat activity; the agent denominator requires agent activity.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: 24 agent sessions among 6 agent users = 4 sessions/user, regardless of how many calendar weeks are selected.

Model references: Average Sessions Per Active User (Licensed), Average Chat Sessions Per Active User (Unlicensed), Average Agent Sessions Per Active Agent User

Application and raw AppHost

App groups equivalent audit hosts under a friendly product name; support tooltips retain raw AppHost. Unknown hosts retain source spelling. App differs from Experience.

Calculation or rule
Not a calculated metric. Map equivalent AppHost values to a friendly App label; retain raw AppHost values in support tooltips.
Dates, filters and population
Application rows/filters within the applicable experience and population.
Assumptions and limitations
Examples: bizchat, office and m365app map to M365 Copilot Chat; outlooksidepane maps to Outlook. Unknown nonblank hosts retain source spelling; blank maps to App not recorded. App is not the same field as Experience.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. App calculated column and Raw AppHost measure.
Worked example
Synthetic: bizchat and office sessions can share the friendly M365 Copilot Chat row; hover lists the raw hosts rather than treating office as a new license product.

Model references: Raw AppHost

Experience

The model's broader activity family: Agents, Cowork, Other AI activity, M365 Copilot, Copilot Chat or Unclassified activity. Explicit precedence and license/host rules determine it.

Calculation or rule
Not a calculated metric. Classify each activity row as Agents, Cowork, Other AI activity, M365 Copilot, Copilot Chat or Unclassified activity using explicit precedence rules.
Dates, filters and population
Usage Explorer and experience selectors.
Assumptions and limitations
AgentId takes precedence over app host. Licensed non-agent rows that survive Cowork/other-product rules are M365 Copilot; only recognized unlicensed hosts become Copilot Chat.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. Power Query Experience transformation; App remains a separate friendly-host field.
Worked example
Synthetic: an agent used inside Teams belongs to Agents with App Teams, not automatically to unlicensed Chat.
Blank, zero and unavailable

Blank can mean no denominator, no records, no selection or protected scope. Zero is a defined numeric result; Unknown, Not recorded and Not stated describe missing evidence.

Calculation or rule
Not a calculated metric. DAX blank can mean no denominator, no selected item, no observed data or a suppressed result. Zero is a defined numeric result; Unknown/Not recorded/Not stated describe missing evidence.
Dates, filters and population
Interpret using the activity-status, metadata and coverage messages for that visual.
Assumptions and limitations
Never replace all blanks with zero. Coverage unavailable, missing catalog ownership and privacy suppression have different causes. An active agent cohort with no repeats explicitly gives 0% return.
Data source and preparation
DAX DIVIDE/BLANK/COALESCE, headcount disclosure measures, Power Query normalization and catalog coverage labels.
Worked example
Synthetic: 0 repeat people/5 active people = 0%. No active people means an undefined return denominator; a protected 2-person group is hidden rather than reported as zero.

Model references: Report Activity Status, Agent Visibility Message, Agent Return Rate (Table)

Activity context

Context_Type is prepared audit context/category evidence used to describe interactions and inform behavior labels. It does not establish a completed task or outcome.

Calculation or rule
Not a calculated metric. Context_Type is a prepared audit context/category field used to group or describe recorded interactions and inform behavior labels.
Dates, filters and population
Applicable application/agent activity and support views.
Assumptions and limitations
A context category is not prompt text, a completed task or a measured outcome. Missing or generic evidence cannot be made more specific by a chart label.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. Context_Type survives preparation; Behavior_Enriched can use it alongside resource/action/plugin/app-host evidence.
Worked example
Synthetic: a stored context suggesting a file interaction can support a pattern label, but does not prove a file was successfully edited or delivered.

People

Eligible people

People belonging to the selected authorized organization, team and license population, including those with no activity. This headcount drives the normal minimum-group check.

Calculation or rule
Count distinct nonblank directory PersonKey values in the applicable population. With license history and a license selection, include people with a qualifying state intersecting the period.
Dates, filters and population
Authorized directory membership after organization, reporting-team, license and usage-band selections. A date/app/agent activity filter does not redefine headcount as only active contributors.
Assumptions and limitations
Includes people with no activity. This is the normal suppression denominator; it is not the active-user numerator. Multiple history states do not create multiple people.
Data source and preparation
Collected Users directory/license observations -> AIO User States -> Chat + Agent Org Data and User License History -> DAX.
Worked example
Synthetic: 20 eligible directory people, of whom 2 have matching activity, means headcount 20 and active users 2. The group passes a threshold of 3.

Model references: Eligible Headcount - All, Eligible Headcount - Licensed, Eligible Headcount - Unlicensed, People in Scope

Active users

Distinct people with relevant recorded activity during the selected dates. Multiple recorded license states do not create extra people.

Calculation or rule
Count distinct PersonKey values with relevant recorded activity, in the current metric context.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
One person can use Chat and agents, or have paid and free states. Population counts overlap and must not be added as if disjoint. No records is not proof of no real-world use.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. PersonKey comes from normalized Users identity/state processing.
Worked example
Synthetic: A uses Chat and agents; B uses Chat. Chat users = 2, agent users = 1, but combined active users = 2.

Model references: Active Users in Scope, Card Active Users

Active licensed users

Licensed people with any recorded experience in scope, including agent-only, Cowork, other AI or unclassified activity. This is broader than licensed chat users.

Calculation or rule
Count distinct licensed people with any recorded activity during the selected period, not just qualifying licensed Chat.
Dates, filters and population
Paid directory population. Snapshot mode checks all activity for those people; history mode uses paid-state membership and licensed activity attribution.
Assumptions and limitations
Agent-only, Cowork, other AI and unclassified records can make a licensed person active. This reconciles with Inactive licensed users, unlike the narrower licensed-chat user count.
Data source and preparation
Collected Users directory/license observations -> AIO User States -> Chat + Agent Org Data and User License History -> DAX. Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: 10 licensed people include 3 Chat users, 2 agent-only users and 5 with no records: active licensed = 5, not 3.

Model references: Active Licensed Users (Any Activity), Card Licensed Users

Inactive licensed users

Licensed people with no recorded activity in the same selected scope. Active plus inactive reconciles to licensed directory headcount in that scope.

Calculation or rule
Licensed directory headcount - active licensed users with any recorded activity.
Dates, filters and population
Same authorized population and dates as the paid activity view. Paid activity selections can narrow the displayed population.
Assumptions and limitations
An agent-only user is active. Blank/protected results are not zero inactive people. Inactivity in audit coverage is not evidence that a license has no value.
Data source and preparation
Collected Users directory/license observations -> AIO User States -> Chat + Agent Org Data and User License History -> DAX. Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX.
Worked example
Synthetic: 10 licensed directory people - 5 active licensed people = 5 inactive. Active 5 + inactive 5 reconciles to 10.

Model references: Total Licensed Users, Active Licensed Users (Any Activity), Inactive Licensed Users

Unlicensed Chat users

People recorded without a Microsoft 365 Copilot license who have qualifying Copilot Chat activity. Agents and unknown-license people are not silently included.

Calculation or rule
Count distinct PersonKey values with Source License Status = Unlicensed and Is Chat Activity = true.
Dates, filters and population
Selected dates and authorized people, reporting teams, organization, license and applicable experience/agent filters. Display grouping and RLS still apply.
Assumptions and limitations
Excludes agent, Cowork, other AI and unclassified rows. Unknown license evidence is not Unlicensed. It is an activity population, not all unlicensed directory people.
Data source and preparation
Purview CopilotInteraction audit evidence -> PAX/preparation prompt-only Interactions rollup -> Power Query Chat + Agent Interactions (Audit Logs) -> DAX. Power Query derives Is Chat Activity from recognized Chat/M365 Copilot experience classification.
Worked example
Synthetic: 8 unlicensed directory people include 3 Chat users and 2 agent-only users. Unlicensed Chat users = 3, not 5 or 8.

Model references: NoOfActiveChatUsers (Unlicensed), Users (Unlicensed)

Unknown license

License evidence is missing or inconclusive. Unknown is kept separate from licensed and unlicensed; it is not assumed to be free.

Calculation or rule
Not a calculated metric. License evidence normalizes to Licensed, Unlicensed or Unknown; missing/unrecognized values map to Unknown.
Dates, filters and population
Directory observations and activity-to-Users matching; Unknown is kept separate from paid/free cohorts.
Assumptions and limitations
TRUE/yes/1 and FALSE/no/0 are recognized evidence. A blank date means an unknown observation date, not necessarily an unknown license status. Source and loaded snapshot statuses can disagree.
Data source and preparation
Collected Users directory/license observations -> AIO User States -> Chat + Agent Org Data and User License History -> DAX. fnAIOUserStates and the Interactions License Data Status transformation preserve missing/disagreement states.
Worked example
Synthetic: Has license is blank: classify Unknown, not free. Has license is FALSE with an undated observation: status can be Unlicensed while First seen remains unknown.
Reporting team

A manager's direct and indirect reports, excluding the manager. Overlapping team selections count a person once and never expand the viewer's access.

Calculation or rule
Not a calculated metric. Select the distinct valid direct and indirect reports of the chosen manager, excluding the manager's own row.
Dates, filters and population
Authorized directory hierarchy; overlapping team selections form a deduplicated membership set.
