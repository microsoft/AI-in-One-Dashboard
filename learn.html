People, prompts and sessions are different.

One person can send several prompts in a conversation and return to it later. The same person can also use chat and agents. Adding daily counts or experience groups can count that person more than once.

Habit summaries focus on one completed month.

Look at the month named on the habit page. If your selected dates end in October, the habit summary describes September. Other activity tables may cover your entire selected date range, so their totals will not necessarily match that one-month summary.

Activity starts a conversation. It does not give a verdict.

More sessions could mean useful work, retries or a difficult task. Scores and inferred use cases do not measure employee performance, answer quality or actual time saved.

What you display.
Who can see it.

Minimum Group Size and row-level security do different jobs. Set up both.

Minimum Group Size

3Default
team-level reporting
1Individual activity
when your policies permit

The threshold counts eligible people in the selected group, including those with no activity. A team of 20 with two active users can show aggregate results at the default setting; a team of two cannot.

Use individual reporting only if your organization's privacy and employee-reporting policies allow it. Check with your privacy or HR team if you are unsure.

This is a display rule, not anonymization. Govern access to the underlying data, exports and Power BI model permissions separately.

How to change the setting

At first template load, enter Minimum Group Size before selecting Load. Later, use Home > Transform data > Manage parameters > Minimum Group Size. Apply changes and clear old filters.

Row-level security (RLS)

These are the two named security roles included in the Power BI model, not titles or job descriptions. Your report owner adds people or security groups to them.

Power BI role name

Reporting hierarchy

Viewers see themselves and their valid direct and indirect reports. If a viewer's sign-in does not match the directory, this role gives them no data.

Power BI role name

All data viewers

Members can see the whole dataset. Use this role only where full access is appropriate under your policies. Adding the same person to Reporting hierarchy does not restrict that full access.

In Power BI Service, open the semantic model > Security, assign members, and Save. Share as Viewer or app consumer and test real viewer accounts. Workspace administrators and contributors are not restricted in the same way.

Protect the source too.

Report roles do not protect CSV files, notebooks, SQL or Fabric OneLake access. Give each source and refresh account only the access it needs.

Understand license history

When we saw a license.
Not when it was assigned.

If collection records someone without a license on Monday and with a license on Friday, we know their recorded status changed. We do not know exactly when it changed between those collections.

When history is retained, the report can use those recorded states to group activity. The person still counts once in the overall total, but may appear in both paid and free groups during the selected period. Do not add those groups to find the total number of people.

Without recorded history, you see the supplied snapshot. Missing license information stays Unknown; it is not treated as "unlicensed." Organization and reporting relationships use the latest person information supplied.

40 definitions

Activity

Prompts

Distinct recorded user request messages, not agent responses. Repeated copies of the same request do not add another prompt; identifier quality affects counts.

Sessions

Distinct person-and-thread conversations in the current selection. The same person returning to the same thread on several days can count once for the whole period.

Prompts per session

Recorded prompts divided by distinct sessions in the same scope. Conversation depth is not duration or business value.

Active days per user

Average distinct dates with recorded activity among active users in scope. It is not hours worked or time spent.

Repeat users and return rate

The share of active users with at least two sessions in the selected period. For agents, 0% means active users but no repeats; blank can mean no activity or protected scope.

Daily repeat-session share

The share of active unlicensed Chat users with more than one Chat session that day. This daily measure differs from repeat users across the full period.

Other AI and Unclassified activity

Other AI can include non-agent autonomous or logic app hosts. Unclassified preserves activity that cannot be confidently assigned; neither category is automatically unlicensed Chat.

Audit coverage

Purview audit data supports security and compliance. Coverage, timing and calculations can differ from Viva Insights and the Microsoft 365 admin center; prompts do not measure responses, duration, time saved or performance.

People

Eligible people

People belonging to the selected authorized organization, team and license population, including those with no activity. This headcount drives the normal minimum-group check.

Active users

Distinct people with relevant recorded activity during the selected dates. Multiple recorded license states do not create extra people.

Active licensed users

Licensed people with any recorded experience in scope, including agent-only, Cowork, other AI or unclassified activity. This is broader than licensed chat users.

Inactive licensed users

Licensed people with no recorded activity in the same selected scope. Active plus inactive reconciles to licensed directory headcount in that scope.

Unlicensed Chat users

People recorded without a Microsoft 365 Copilot license who have qualifying Copilot Chat activity. Agents and unknown-license people are not silently included.

Unknown license

License evidence is missing or inconclusive. Unknown is kept separate from licensed and unlicensed; it is not assumed to be free.

Reporting team

A manager's direct and indirect reports, excluding the manager. Overlapping team selections count a person once and never expand the viewer's access.

Time

Observed license history

When collection keeps license history, the report remembers the license information recorded for each person. It uses those observations to group their activity. Changes that happened between observations may not be recorded.

First seen

The date a license state was observed, not when the license was assigned. Undated evidence remains Unknown; a current snapshot cannot recover earlier transitions.

Monthly paid/free membership

Paid membership includes people with a licensed state at any point in that month. A person can also appear in free membership, so distinct totals can be smaller than the sum.

Per active week

A person's relevant activity divided by weeks in which that person was active. Read the chart label: some views average these person-level rates; others show totals or per-user rates.

Habit month and bands

The month before the selected end date. Light is 1-5, Moderate 6-10, Frequent 11-15 and Daily 16+ distinct active days; zero-day people are outside these fixed bands.

Comparisons

Dynamic usage bands

Percentile bands use distinct prompts per active week among active peers in each rank family. Dates and authorized population set thresholds; ties share a band. Independent family selections intersect without recalculating each other.

Individual priority rank

A relative unlicensed Chat comparison among selected peers in the same manager team, or the department root. Rank 1 is highest; ties share a rank. Individual reporting must be permitted by your organization's policies. This is not a performance rating.

License priority score

An uncapped heuristic: 60% weekly volume / 10, 30% active days per week / 5, and 10% volume per active day / 5. Sessions is default; Prompts uses the same weights and benchmarks in prompt units.

Agent engagement comparison

Equal-weight peer percentile ranks for return rate, sessions per user and prompts per session, requiring MAX(Minimum Group Size, 5) users. Sessions, then name, break ties; this is not business value.

Privacy

Minimum Group Size

The smallest eligible group whose results can be displayed. The default is 3 people. A setting of 1 enables individual activity; use it only if your organization's privacy and employee-reporting policies permit it. This setting does not replace access controls or anonymize the data.

Reporting hierarchy role

RLS matches the signed-in viewer's normalized UPN to a directory person and permits their own row and valid descendants. An unmatched identity receives no data.

All data viewers role

RLS role for explicitly authorized full-model access, initially with no members. Roles are additive; this role is not restricted by also belonging to Reporting hierarchy.

Agents

Creator

Catalog ownership metadata: Created by, then legacy Agent creator. Missing values say Not recorded. Creator metadata can be visible at group size 3 without exposing individual usage.

Developer Name

The agent developer or publisher, separate from Creator. Missing or generic placeholders say Not stated. A third-party store publisher is not a creator in your tenant.

Agent type

Where an agent was created, such as Copilot Studio or Agent Builder. Catalog labels are used when that information is missing. Type is separate from whether the agent matches the catalog.

Catalog status

In catalog, Not in Agent 365 catalog (activity only), or Ambiguous catalog match. Catalog agents count distinct Title IDs, not names; export timing can affect matching.

Features

Catalog-listed supported surfaces and capabilities, such as Teams, Outlook, SharePoint or files. Listed support does not demonstrate recorded use of that feature.

System-generated agents

Special catalog entries excluded by default. Include system agents in Org filters to see them; they are not ordinary builder or action-oriented review targets.

Usage not tracked here

Security Copilot catalog entries have activity outside this dashboard's tracking scope. This label is not evidence that the agent has never been used.

Dormant and No usage

Dormant means previously used with last activity more than 60 days before the selected end. Never-used agents are No usage, not Dormant; labels follow the selected scope.

Inferred usage patterns

Stored PAX behavior labels use resource/action/context/plugin/app-host evidence and sometimes agent names, not prompt-text analysis or AI inference. Not enough activity to infer explains missing evidence.

Setup

Prepared inputs

Matching Users and Interactions files prepared by PAX, or the tables required by your chosen Fabric OneLake edition. Raw audit exports cannot be used in place of these prepared inputs.

Refresh

Fabric OneLake notebook readiness

The Fabric OneLake preparation notebook marks its report tables Ready after its checks succeed. The SQL analytics endpoint must also finish synchronizing before Power BI refresh. Do not update tables during that refresh.

Fabric OneLake PAX readiness

PAX must finish updating the matching Fabric OneLake tables before Power BI refresh. Wait for SQL synchronization and keep table updates paused for the entire refresh. Template checks of data structure and user links do not prove every table comes from the same completed update.

Power BI Import

Power BI keeps an imported copy of the source data and updates it when the report refreshes. Both Fabric OneLake editions use the Lakehouse SQL analytics endpoint, not Direct Lake. Source access and report-viewer access are separate.
