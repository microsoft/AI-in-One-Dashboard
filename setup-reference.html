Prepare the environment

Edition: Fabric OneLake: Notebooks
  1. Install PowerShell 7+ (opens a new tab) and Python 3.10+ (opens a new tab) on the collection computer. Allow approved module/package installation, outbound Graph/storage access and a writable working folder. PowerShell must use FullLanguage mode.
  2. Download the PAX v2 script and keep its actual filename and version.
  3. Run as the intended collection account. Check $PSVersionTable.PSVersion, $ExecutionContext.SessionState.LanguageMode and python --version.

Fabric Delta output also requires Az.Accounts, pyarrow and deltalake, an active Fabric capacity and a target Lakehouse.

Prepare Fabric

  1. Use an active Fabric-capable capacity and a workspace with a dedicated Lakehouse. PPU alone is not a notebook/Lakehouse capacity.
  2. Give the actual notebook execution identity workspace Contributor or higher and the required Key Vault secret-read access. An interactive run and a scheduled/pipeline run may use different identities; test the configured execution connection.
  3. Reserve the same default Lakehouse for all four imported notebooks. Do not overlap collection/preparation with the report refresh.

Agree the reporting scope: dates, people, viewer access and refresh frequency must follow the organization's approvals. Identify the collection operator and report owner; keep credentials out of tickets and this site.

Manual browser / device code

  1. Use PAX's default browser sign-in, or -Auth DeviceCode. Authorize the requested delegated scopes with tenant administrator consent as required.
  2. The reviewed PAX implementation uses the Graph PowerShell default application for these modes. A new custom app registration, client ID or Redirect URI is not selected by supplying PAX tenant/client flags.
  3. Assign the operator the approved audit-search authorization. Microsoft documents Purview Audit Reader/Audit Manager for search/export and Security Reader/Administrator for general delegated Graph Security access. Prove an audit query with the intended account; do not substitute a Global Administrator account as the standard operator.
  4. For delegated catalog collection, verify AI Administrator or Global Administrator and Agent 365 entitlement. For scheduled collection, choose app-only instead; browser/device modes require a person.

Register an unattended application

  1. Entra admin center → App registrations → New registration. Select the source organization's single tenant. Record Directory (tenant) ID and Application (client) ID, not the app object ID. Client-credentials sign-in needs no interactive Redirect URI or public-client setting.
  2. API permissions → Add a permission → Microsoft Graph → Application permissions. Add only the applicable entries in the matrix. Have an authorized tenant administrator grant admin consent; confirm “Granted for” the source tenant. Privileged Role Administrator can grant Graph application permissions; Application/Cloud Application Administrator alone is not sufficient for Graph app roles.
  3. In Certificates & secrets → Certificates, upload the public certificate. Install its corresponding private key for the scheduled account, grant that account private-key access, and record thumbprint/store. Keep GRAPH_CLIENT_SECRET out of the certificate-only process because a secret can take precedence.
  4. In Certificates & secrets → Client secrets, create the approved short-lived credential. Store its Value, not secret ID, in the organization's secret store. Inject GRAPH_TENANT_ID, GRAPH_CLIENT_ID and GRAPH_CLIENT_SECRET into the task's process. Do not put secret values in scripts, URLs, tickets or Mini-Kitchen.
  5. Record rotation/expiry ownership. Validate authentication as the actual task identity before enabling a schedule.
# Run as the identity that will own the scheduled task.
# IT supplies a certificate with a usable private key in that account's
# CurrentUser store or the approved LocalMachine store.
$Auth = @{
    Auth = 'AppRegistration'
    TenantId = '<tenant GUID>'
    ClientId = '<application client GUID>'
    ClientCertificateThumbprint = '<certificate thumbprint>'
    ClientCertificateStoreLocation = 'LocalMachine'
}
if ($env:GRAPH_CLIENT_SECRET) {
    throw 'Remove the unintended secret from this certificate-only task environment.'
}

Azure managed identity

  1. Assign the managed identity to the Azure PowerShell host. Grant the applicable Graph application roles with tenant administrator consent to its service principal; there is no client secret and it is not configured under App registrations.
  2. Use -Auth ManagedIdentity. For a user-assigned identity, configure AZURE_CLIENT_ID on the host; do not use -ClientId to select it.
  3. Grant destination access independently and run a collection using that resource's identity. A laptop cannot impersonate the host's managed identity.

Notebook Graph application + Key Vault

  1. Register a single-tenant app in the source tenant. Add Microsoft Graph Application permissions AuditLogsQuery.Read.All, User.Read.All and Reports.Read.All; grant tenant administrator consent.
  2. Create a client secret and store its Value in Azure Key Vault under an IT-chosen secret name. The supplied collectors implement client-secret authentication; choosing a certificate without adapting them will not work.
  3. Grant the notebook execution identity Key Vault Secrets User in an RBAC vault, or secret Get in an access-policy vault. Key Vault Reader/Contributor does not grant secret-value reads. Confirm networking allows access.
  4. Keep tenant/client IDs as notebook parameters. Only the client-secret value must be in Key Vault. Plan rotation and test the actual scheduled execution connection.

SharePoint storage permissions

Apply the SharePoint permissions listed above to the destination site and library. Prepare the output folder before collection.

  1. Consent to Microsoft Graph Delegated Sites.ReadWrite.All for the PAX sign-in application.
  2. Give the signed-in collection account Edit access to the destination library/folder. Graph consent does not give the user access to a site.
  1. Add Microsoft Graph Application Sites.Selected to the collector app (or the managed identity's service principal), and grant administrator consent.
  2. Separately grant that principal write on the destination site using the site's ID and the collector's application/client ID. Consent to Sites.Selected alone grants no site access.

An authorized grant administrator can use the request below. Their Graph needs Sites.FullControl.All; a delegated administrator also needs SharePoint Administrator or higher and membership of the target site. This elevated permission is for the granting session, not the collector.

POST https://graph.microsoft.com/v1.0/sites/{site-id}/permissions
Content-Type: application/json

{
  "roles": ["write"],
  "grantedToIdentities": [{
    "application": {
      "id": "<collector application client ID>",
      "displayName": "AIO PAX collector"
    }
  }]
}

If an existing policy-approved collector already uses Application Sites.ReadWrite.All, it has tenant-wide site-write access and does not also need a Selected-site grant. Prefer the site-scoped grant for a new deployment.

Report refresh: give the report's organizational account Read access to every processed CSV in the library. It does not need the collector's write permission. Test an upload as the collector and a file read as the refresh account.

Publish, secure and schedule

Edition: Fabric OneLake: Notebooks
  1. Publish to the approved Power BI workspace as the intended semantic-model owner. Confirm the publisher's license and a compatible viewer license/capacity model. Pro/shared workspaces need suitable paid viewer licenses; PPU workspaces need PPU; F64+ or qualifying Premium capacity can support Free viewers.
  2. Semantic model → Settings → Gateway and cloud connections: map the exact cloud source or gateway, configure approved reader credentials, run Refresh now, and inspect refresh history. The model owner configures schedule/credentials; merely granting write/refresh permission is not equivalent.
  3. Semantic model → Security: assign the approved audiences to Reporting hierarchy (their own organization) or All data viewers (unrestricted dataset). Roles are additive; All data viewers overrides the intended hierarchy restriction.
  4. Distribute through an app or Viewer access. Workspace Admins/Members/Contributors bypass normal viewer RLS; do not use those roles just to view. Test as actual Viewer/app identities, including an unmatched account expected to see no hierarchy data.
  5. If scheduled updates are needed, run source updates first, confirm readiness, then refresh the model. Keep table writes separate from Import refresh. Test the configured schedule with its actual collection and refresh identities.

Edition: Fabric OneLake: Notebooks

Metric glossary

Definitions for this AIO report. Microsoft reference links provide background, not equivalent formulas.

Find the meaning

A glossary you can scan.

Jump to a topic or search across all definitions. Your place stays highlighted as you read.

Glossary overviewActivityPeopleTimeComparisonsPrivacyAgentsSetupRefresh

42 definitions

Activity

Usage

Recorded activity within the selected dates, people and experiences. Read the specific metric: prompts, sessions and active users count different things. Usage is not a measure of time saved, answer quality or employee performance.

Actions

Recorded action or operation evidence can help describe an inferred usage pattern. It does not by itself prove a task was completed or a business outcome was achieved.

Prompts

Distinct recorded user request messages, not agent responses. Repeated copies of the same request do not add another prompt; identifier quality affects counts.

Microsoft Learn: Copilot audit records (opens a new tab)Source context. AIO applies its own prompt selection and counting rules.

Sessions

Distinct person-and-thread conversations in the current selection. The same person returning to the same thread on several days can count once for the whole period.

Prompts per session

Recorded prompts divided by distinct sessions in the same scope. Conversation depth is not duration or business value.

Active days per user

Average distinct dates with recorded activity among active users in scope. It is not hours worked or time spent.

Repeat users and return rate

The share of active users with at least two sessions in the selected period. For agents, 0% means active users but no repeats; blank can mean no activity or protected scope.

Daily repeat-session share

The share of active unlicensed Chat users with more than one Chat session that day. This daily measure differs from repeat users across the full period.

Other AI and Unclassified activity

Other AI can include non-agent autonomous or logic app hosts. Unclassified preserves activity that cannot be confidently assigned; neither category is automatically unlicensed Chat.

Audit coverage

Purview audit data supports security and compliance. Coverage, timing and calculations can differ from Viva Insights and the Microsoft 365 admin center; prompts do not measure responses, duration, time saved or performance.

Microsoft Learn: why usage-report counts differ (opens a new tab)Comparison only. Official usage-report populations and calculations are not AIO definitions.

People

Eligible people

People belonging to the selected authorized organization, team and license population, including those with no activity. This headcount drives the normal minimum-group check.

Active users

Distinct people with relevant recorded activity during the selected dates. Multiple recorded license states do not create extra people.

Active licensed users

Licensed people with any recorded experience in scope, including agent-only, Cowork, other AI or unclassified activity. This is broader than licensed chat users.

Microsoft Learn: why usage-report counts differ (opens a new tab)Comparison only. Official usage-report populations and calculations are not AIO definitions.

Inactive licensed users

Licensed people with no recorded activity in the same selected scope. Active plus inactive reconciles to licensed directory headcount in that scope.

Microsoft Learn: why usage-report counts differ (opens a new tab)Comparison only. Official usage-report populations and calculations are not AIO definitions.

Unlicensed Chat users

People recorded without a Microsoft 365 Copilot license who have qualifying Copilot Chat activity. Agents and unknown-license people are not silently included.

Unknown license

License evidence is missing or inconclusive. Unknown is kept separate from licensed and unlicensed; it is not assumed to be free.

Reporting team

A manager's direct and indirect reports, excluding the manager. Overlapping team selections count a person once and never expand the viewer's access.

Time

Observed license history

When collection keeps license history, the report remembers the license information recorded for each person. It uses those observations to group their activity. Changes that happened between observations may not be recorded.

First seen

The date a license state was observed, not when the license was assigned. Undated evidence remains Unknown; a current snapshot cannot recover earlier transitions.

Monthly paid/free membership

Paid membership includes people with a licensed state at any point in that month. A person can also appear in free membership, so distinct totals can be smaller than the sum.

Per active week

A person's relevant activity divided by weeks in which that person was active. Read the chart label: some views average these person-level rates; others show totals or per-user rates.

Habit month and bands

The month before the selected end date. Light is 1-5, Moderate 6-10, Frequent 11-15 and Daily 16+ distinct active days; zero-day people are outside these fixed bands.

Comparisons

Dynamic usage bands

Percentile bands use distinct prompts per active week among active peers in each rank family. Dates and authorized population set thresholds; ties share a band. Independent family selections intersect without recalculating each other.

Individual priority rank

A relative unlicensed Chat comparison among selected peers in the same manager team, or the department root. Rank 1 is highest; ties share a rank. Individual reporting must be permitted by your organization's policies. This is not a performance rating.

License priority score

An uncapped heuristic: 60% weekly volume / 10, 30% active days per week / 5, and 10% volume per active day / 5. Sessions is default; Prompts uses the same weights and benchmarks in prompt units.

Agent engagement comparison

Equal-weight peer percentile ranks for return rate, sessions per user and prompts per session, requiring MAX(Minimum Group Size, 5) users. Sessions, then name, break ties; this is not business value.

Privacy

Minimum Group Size

The smallest eligible group whose results can be displayed. The default is 3 people. A setting of 1 enables individual activity; use it only if your organization's privacy and employee-reporting policies permit it. This setting does not replace access controls or anonymize the data.

Reporting hierarchy role

RLS matches the signed-in viewer's normalized UPN to a directory person and permits their own row and valid descendants. An unmatched identity receives no data.

Microsoft Learn: Power BI row-level security (opens a new tab)Platform guidance. Reporting hierarchy and All data viewers are roles supplied by AIO.

All data viewers role

RLS role for explicitly authorized full-model access, initially with no members. Roles are additive; this role is not restricted by also belonging to Reporting hierarchy.

Agents

Creator

Catalog ownership metadata: Created by, then legacy Agent creator. Missing values say Not recorded. Creator metadata can be visible at group size 3 without exposing individual usage.

Developer Name

The agent developer or publisher, separate from Creator. Missing or generic placeholders say Not stated. A third-party store publisher is not a creator in your tenant.

Agent type

Where an agent was created, such as Copilot Studio or Agent Builder. Catalog labels are used when that information is missing. Type is separate from whether the agent matches the catalog.

Catalog status

In catalog, Not in Agent 365 catalog (activity only), or Ambiguous catalog match. Catalog agents count distinct Title IDs, not names; export timing can affect matching.

Features

Catalog-listed supported surfaces and capabilities, such as Teams, Outlook, SharePoint or files. Listed support does not demonstrate recorded use of that feature.

System-generated agents

Special catalog entries excluded by default. Include system agents in Org filters to see them; they are not ordinary builder or action-oriented review targets.

Usage not tracked here

Security Copilot catalog entries have activity outside this dashboard's tracking scope. This label is not evidence that the agent has never been used.

Dormant and No usage

Dormant means previously used with last activity more than 60 days before the selected end. Never-used agents are No usage, not Dormant; labels follow the selected scope.

Inferred usage patterns

Stored PAX behavior labels use resource/action/context/plugin/app-host evidence and sometimes agent names, not prompt-text analysis or AI inference. Not enough activity to infer explains missing evidence.

Refresh

Fabric OneLake notebook readiness

The Fabric OneLake preparation notebook marks its report tables Ready after its checks succeed. The SQL analytics endpoint must also finish synchronizing before Power BI refresh. Do not update tables during that refresh.

Fabric OneLake PAX readiness

PAX must finish updating the matching Fabric OneLake tables before Power BI refresh. Wait for SQL synchronization and keep table updates paused for the entire refresh. Template checks of data structure and user links do not prove every table comes from the same completed update.

Power BI Import

Power BI keeps an imported copy of the source data and updates it when the report refreshes. Both Fabric OneLake editions use the Lakehouse SQL analytics endpoint, not Direct Lake. Source access and report-viewer access are separate.
