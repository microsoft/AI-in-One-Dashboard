IT setup & permissions

Get the right access.
Make setup simpler.

A practical reference for the person who configures collection, source connections and scheduled refresh. Start with the sign-in method you will use.

Before collection

The person requesting the report should explain what they want to understand and who will use it. IT helps with access, collection and the technical setup.

  • Install current Power BI Desktop. Confirm the Power BI licenses or capacity needed for sharing.
  • For PAX, install PowerShell 7 or later and Python 3.10 or later. Mini-Kitchen provides the PAX download and the commands for both the first collection and ongoing updates.
  • Check Purview audit logging (opens a new tab) and the history available under the tenant's retention policy. Newly enabled logging does not recover earlier activity.
  • Choose a secure destination and give the collection account write access and the Power BI refresh account read access.
  • For Fabric OneLake, confirm capacity, Lakehouse access and a readable SQL analytics endpoint.

Choose the permission model, not just the app registration.

Microsoft Entra app registrations can have Delegated permissions or Application permissions. These are different access models. A certificate or secret is a credential, not a permission model.

Delegated permissions

A person signs in

The app acts on that person's behalf. Both the delegated permission and the signed-in person's access matter.

Application permissions

The app signs in on its own

Permissions belong to the app or managed identity. An administrator grants consent before an unattended run.

For PAX, the AppRegistration sign-in option is app-only. Browser and device sign-in use a delegated user context. Do not add delegated permissions and expect them to authorize an app-only run, or vice versa.

PAX with a signed-in person: Delegated permissions

In the app registration used for user sign-in, choose Microsoft Graph > Delegated permissions. PAX requests the scopes for the features you collect; your tenant's consent policy determines who can consent.

SharePoint: interactive PAX requests delegated Sites.ReadWrite.All. The signed-in person must already be able to edit the destination site and library. This does not grant them access to every site.

Agent 365: delegated catalog collection also requires the signed-in person's appropriate directory role, such as AI Administrator or Global Administrator, and tenant eligibility for Agent 365.

Use Mini-Kitchen to choose the interactive sign-in method. Registering an app alone does not grant the user the necessary tenant roles or source access.

PAX without a user sign-in: Application permissions

For app-only collection, choose Microsoft Graph > Application permissions on the app registration and grant administrator consent. Managed identities need the equivalent application permissions on their service principal.

CollectingMicrosoft Graph permission
Copilot and agent activityAuditLogsQuery.Read.All
People, departments and licensingUser.Read.All and Organization.Read.All
Agent 365 catalog, when collectedCopilotPackages.Read.All and Application.Read.All
Security-group filtering, when usedGroupMember.Read.All

SharePoint: grant Sites.Selected, then separately grant the app or managed identity write access to each intended destination site. Sites.Selected alone gives access to no sites.

Agent 365: the application permissions belong to the app or managed identity, rather than a signed-in administrator. Tenant eligibility still applies.

Use Mini-Kitchen to configure the app-only sign-in and commands. Protect credentials using your organization's secret-management practices; do not send them in the IT request or paste them into public pages.

Fabric OneLake notebooks: Application permissions

The collector application needs Microsoft Graph Application permissions with administrator consent: AuditLogsQuery.Read.All, User.Read.All and Reports.Read.All. This differs from PAX's collection permission set.

The notebook execution account needs Lakehouse table-write access and permission to retrieve the designated client secret from Azure Key Vault. Preparation needs notebook execution and Lakehouse access; reading a processed PAX CSV pair directly does not require the Graph collectors.

Collection access is not report access.

Power BI refresh needs its own source read access. Viewers need report access and the appropriate model security role. These do not replace one another.

Use Mini-Kitchen from the first collection onward.

Mini-Kitchen creates commands for both your first collection and later updates. It also links to the PAX script download. It does not run the commands or connect to your tenant.

  1. Start with the history you need. In Mini-Kitchen, choose AI-in-One, your dates, storage destination and sign-in method. Download PAX there and run the generated command.
  2. Keep the matching results together. PAX prepares the people, activity and optional agent catalog for the report. Record their locations so Power BI can use them.
  3. Add new days to those same results. Return to Mini-Kitchen for an update command. Point it at the existing outputs so the report keeps the same connections.
  4. Schedule if needed. IT can schedule the generated update command with the right sign-in method. Mini-Kitchen creates the command; the schedule runs it.
  5. Refresh Power BI afterward. Wait for a successful, complete data update and any cloud synchronization before the report refresh begins.
Administrator detail: dates, watermarks and license history

The initial PAX collection uses -StartDate and an exclusive -EndDate. Watermark updates use -Watermark and the exact existing outputs through append parameters. The first watermark also uses -WatermarkStartDate for the first day not yet collected; later updates omit it and omit StartDate/EndDate. Dates cover complete UTC days.

When your collection process uses -UserHistory On, it can retain license states observed going forward. It does not recover changes that were never collected. Use matching Users and Interactions from the same collection history.

Mini-Kitchen explains the switches and creates the commands for each stage.

SharePoint: connect the matching CSV files.

  1. Use Mini-Kitchen to create the AI-in-One collection command with a SharePoint destination. Set up delegated or application permissions for the sign-in method you choose.
  2. Let PAX finish writing the matching processed Interactions and Users CSV files. Include the optional Agent 365 catalog if you want its metadata.
  3. For each CSV, open its SharePoint library, select the file, open Details and copy Path. Use the direct HTTPS CSV path, not a sharing link or the browser address bar.
  4. Open the SharePoint template in Power BI Desktop. Paste the Interactions path into Copilot Interactions File, the Users path into Org Data File, and the optional catalog path into Agent 365. Keep Minimum Group Size at 3 unless your policies permit another setting.
  5. Select Load and sign in with the organizational account that can read the files.
  6. In Power BI Service, configure organizational OAuth2 credentials for each source and test Refresh now. Schedule refresh after PAX has successfully finished; a gateway is normally unnecessary.

Raw audit exports are not substitutes for processed CSVs. The account collecting data needs write access; the account refreshing the report needs read access. Continue to report security and sharing before giving viewers access.

Local CSV: connect files on a PC or network.

  1. Use Mini-Kitchen for the first AI-in-One collection and later updates, choosing a local output folder. For a fictional trial, use the sample data instead; PAX is not needed.
  2. Keep the matching processed Users and Interactions CSV files together. For the sample, extract the Interactions CSV from the ZIP first.
  3. In File Explorer, use Copy as path. Remove the surrounding quotation marks before pasting into Power BI.
  4. Open the Local CSV template in Power BI Desktop. Set Copilot Interactions File to the activity CSV and Org Data File to the Users CSV. Set Agent 365 to the catalog CSV if you have one; otherwise leave it blank.
  5. Keep Minimum Group Size at 3 for team-level reporting and select Load.
  6. Refresh directly in Desktop. For scheduled Service refresh, install and configure an on-premises data gateway that can read those same paths. Otherwise, refresh in Desktop and republish.

For shared reporting, continue to viewer access and sharing. Source-file access and report-viewer access are separate.

Fabric OneLake: notebook collection

This route uses three collector notebooks and a preparation notebook, all attached to the same default Lakehouse. The collectors call Microsoft Graph; Power BI refresh does not. The report imports prepared tables through the SQL analytics endpoint.

  1. Give the collector application the required audit, directory and reporting permissions. Store its client secret in Azure Key Vault and give the notebook execution account permission to retrieve it.
  2. Import the four notebooks and attach the same Lakehouse. Configure tenant/client identifiers and Key Vault references; never paste secret values into cells.
  3. Run the audit, organization and licensing collectors, then preparation. The pipeline can coordinate this order.
  4. Preparation checks input age, tenant, identities, keys and output consistency. It publishes aio_v2_users, aio_v2_interactions and aio_v2_publication.
  5. Wait for SQL to show the completed tables with a matching Ready publication. A Ready marker in the Lakehouse alone does not prove SQL synchronization.
  6. Configure the Power BI SQL cloud connection, plus separate SharePoint credentials if the optional catalog is used. Keep updates and Power BI Import refresh non-overlapping.

Blank manager references can be intentional top-of-chain records. Missing requested managers and cycles need careful source review; do not invent reporting relationships to grant access.

Alternative: prepare an existing pair of PAX CSV files

The preparation notebook can accept both processed Users and Interactions CSV paths in Lakehouse Files. Supply a matching pair, not raw audit exports. Run preparation directly for this option; the supplied pipeline still runs its Graph collectors. This still produces the Fabric OneLake notebook edition's prepared tables, not the direct Fabric OneLake PAX connection.

Fabric OneLake: PAX collection

This separate connection reads PAX-prepared AIO_Users and AIO_CopilotInteractions tables and optionally Agent365. It does not run the notebook collectors or preparation.

  1. Let the entire PAX data update finish successfully and wait for SQL synchronization.
  2. Enter the SQL endpoint, Lakehouse database, physical schema and optional catalog setting. Use the existing parameters, not a OneLake file URL.
  3. The template checks required columns, data types, unique Users state keys and activity-to-Users relationships. These checks do not prove every table comes from one completed update.
  4. Schedule the SQL Import refresh after your normal PAX completion and SQL synchronization window. Exclude all table writers for the entire refresh.

Configure Power BI refresh

SharePoint: set organizational OAuth2 credentials with read access to each file. A gateway is normally unnecessary.

Local or network CSV: configure an on-premises data gateway that can read the same paths, or refresh in Desktop and republish.

Fabric OneLake: use a SQL cloud connection for the refresh account. The report is Import, not Direct Lake. Private networking or tenant policies may add requirements.

Test Refresh now, then confirm a later scheduled run succeeds. Viewer security roles do not grant the refresh account source access, and source access does not grant report-viewer access.
